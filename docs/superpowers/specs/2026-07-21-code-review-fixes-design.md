# 代码审查问题修复设计

## 1. 目标与范围

修复当前代码审查确认的五个一致性问题：病人删除的数据库/文件状态、DICOM 方向浮点比较、病人表单保存期间关闭、轴位视口尺寸同步，以及轴位 runtime 未就绪时的交互丢失。

本次只修改直接相关的服务、组件和测试；不增加数据库表、后台任务、通用状态框架或新产品功能。

## 2. 修复决策

### 2.1 病人删除一致性

病人目录移动到 `.delete-staging` 之后、数据库提交之前仍是可逆阶段：数据库提交失败时恢复目录并保留数据库记录。数据库删除提交成功后进入不可逆清理阶段：即使清理暂存目录时只删除了一部分文件后失败，也不再恢复数据库快照或原目录，避免重新产生指向缺失文件的 Instance 记录。

清理失败仍返回稳定的持久化错误；未删除完的暂存目录保留在隔离区，可使用现有 `purge_patient_delete` 重试。这样优先保证可访问数据库不会引用已删除文件，同时不会吞掉残留隐私数据的清理失败。

### 2.2 DICOM 方向容差

后端与前端统一采用 `1e-6` 的逐分量绝对误差：六个方向分量都在容差内时视为同一方向；任一分量超过容差时仍标记为 `inconsistent_orientation`。不引入额外归一化或角度模型。

### 2.3 表单保存期间关闭

`saving` 为真时，取消按钮禁用，取消回调直接返回；Esc 和遮罩关闭继续走同一个受保护回调。保存请求完成后只执行既有 `onSaved` 路径，不引入请求取消语义。

### 2.4 轴位视口尺寸同步

`AxialViewportRuntime` 增加小型 `resize()` 接口，内部直接调用当前 `renderingEngine.resize()`。组件的 `ResizeObserver` 只调用当前 runtime 的 `resize()`，不再派发没有监听者的全局 `window.resize`。

### 2.5 轴位 runtime 就绪状态

组件显式维护 runtime 是否就绪。创建完成前禁用工具切换、上一张、下一张和重置，并显示加载提示；创建成功后才开放交互。重试、image IDs 变化或卸载时重新进入未就绪状态，避免 React 工具状态先于 Cornerstone runtime 更新。

## 3. 验证标准

- 模拟 purge 已删除至少一个文件后抛错：数据库中的 Patient/Study/Series/Instance 仍保持删除，剩余隔离目录可再次清理。
- 方向分量差值不超过 `1e-6` 时 Series 可查看，超过时保持 `inconsistent_orientation`。
- 保存 Promise 未完成时，取消按钮和 Esc 均不能关闭表单；完成后保存回调只发生一次。
- 容器 resize 时调用 runtime 的 `resize()`，并最终到达 `renderingEngine.resize()`。
- runtime Promise 未完成时所有会依赖 runtime 的控件禁用；完成后恢复可操作。
- 后端全量 pytest、前端全量 Vitest 和 `tsc --noEmit` 全部通过。

## 4. 风险与边界

- purge 失败后 API 会报告失败，但数据库删除已提交；这是为避免“看似存在但文件缺失”的更危险状态而选择的明确边界。残留隔离目录仍需后续重试清理。
- `1e-6` 仅解决序列内轻微浮点序列化差异，不改变 DICOM 几何完整性或正交性判断。
- 前端只阻止保存期间关闭，不改变既有保存错误后的重试体验。
