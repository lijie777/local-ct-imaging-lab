# 公开仓库与双语 README 设计

## 背景

仓库 `lijie777/local-ct-imaging-lab` 当前为 private，根 `README.md` 仅提供中文说明。用户希望将仓库改为 public，并让 README 同时支持中文与英文切换。

## 目标

1. 保留中文作为 GitHub 默认展示语言。
2. 提供内容完整、与中文版语义一致的英文 README。
3. 让读者可以在两份 README 顶部直接切换语言。
4. 在公开仓库前检查已跟踪内容是否包含凭据、真实患者数据、运行数据或不应公开的本机信息。
5. 将文档改动提交并推送到 `origin/main`，再把 GitHub 仓库可见性改为 public 并复核结果。

## 方案选择

采用两个独立 README 文件：

- `README.md`：中文默认页，顶部显示 `中文 | English`，其中 English 链接到 `README.en.md`。
- `README.en.md`：英文页，顶部显示 `中文 | English`，其中中文链接回 `README.md`。

未采用单文件中英上下排列，因为现有 README 篇幅较长，重复内容会明显降低导航和维护体验。未采用英文作为根 README，因为当前项目的主要维护与使用语境为中文。

## 内容结构

英文版与现有中文版保持相同章节顺序和信息覆盖：

1. 项目名称和非临床声明。
2. 背景与目的。
3. 已完成功能。
4. 系统架构与数据流。
5. 技术栈和目录结构。
6. 环境要求与开发模式启动。
7. FastAPI 托管 `frontend/dist` 的 production 单进程运行方式。
8. 本机数据目录、导入限制、临时目录和删除隔离语义。
9. 基本使用流程。
10. 后端测试、前端测试和 production build。
11. Feature 文档导航。
12. 当前限制、明确排除和已知非阻断 warning。

命令、环境变量、路径、API 名称、版本号和文档链接保持原样；英文仅翻译解释性文字。中文版除增加语言切换入口外，不改变现有技术含义。

## 公开前检查

检查范围为当前提交将公开的全部已跟踪文件，以及本次新增的 README 和设计/计划文档：

- 搜索常见凭据名称、私钥头、访问令牌和密码赋值模式。
- 检查是否跟踪 SQLite、DICOM、上传文件、临时目录或其他运行数据。
- 搜索用户目录、本机仓库绝对路径和可能暴露个人环境的信息。
- 确认文档继续明确要求仅使用脱敏教学数据，并保留“不用于临床诊断”的边界。

发现疑似敏感项时停止公开操作，先确认并清理；扫描无异常后才执行远程可见性修改。

## 验证

- 比较两份 README 的标题层级，确保章节一一对应。
- 验证两份 README 的语言切换链接和全部本地相对链接均指向已存在文件。
- 运行 `git diff --check`，确保没有空白字符错误。
- 检查最终提交仅包含本次双语文档和流程文档。
- 推送后确认 `origin/main` 指向新提交。
- 使用 GitHub CLI 查询 `lijie777/local-ct-imaging-lab`，确认 `visibility` 为 `PUBLIC`。

## 发布顺序

1. 生成并验证双语 README。
2. 完成公开前敏感信息检查。
3. 按确认后的文档范围提交并推送 `main`。
4. 执行 GitHub 仓库可见性修改。
5. 重新查询远程仓库 URL、默认分支和可见性。

先推送文档再公开，可确保仓库首次变为 public 时已经具备完整的中英文入口和安全边界说明。

## 明确边界

- 不修改后端、前端、测试、依赖或运行配置。
- 不改写历史规格、计划和验收证据。
- 不新增 GitHub Pages、自动翻译或语言选择脚本。
- 不新增或变更软件许可证；本次只调整仓库可见性和 README 文档。
- 不创建 Release、tag、PR 或新分支。

## 完成标准

1. GitHub 默认显示中文 `README.md`，可一键切换到完整英文版并返回。
2. 中英文 README 的技术信息、命令、安全声明和限制保持一致。
3. 所有相对链接和 Markdown 基础检查通过。
4. 公开前扫描未发现需要阻止发布的敏感内容或运行数据。
5. 文档提交已推送到 `origin/main`。
6. GitHub 返回仓库可见性为 `PUBLIC`。
