# Feature Specification: 轴位 CT 查看器

**Feature Branch**: `003-axial-viewer`

**Created**: 2026-07-20

**Status**: Complete

**Input**: User description: "继续执行下一个功能；采用默认或推荐方案，实现从已导入 DICOM CT 序列打开轴位查看器。"

## Constitutional Constraints *(mandatory)*

- **Safety notice**: 病人管理页的 Series 入口、轴位查看页、影像加载状态、空状态和失败状态顶部
  必须持续、清晰地显示“教学演示软件，不用于临床诊断”。任何画布、工具栏或错误覆盖层不得遮挡
  完整提示。
- **Data boundary**: 本功能仅供一名本地用户离线使用。病人信息、Study/Series/Instance 元数据、
  DICOM 文件和解码后的像素不得离开本机；所有影像请求只能访问本机服务，不得上传、同步、遥测
  或连接外部影像服务。
- **Scope boundary**: 本功能不得加入云服务、登录认证、PACS、DICOMweb、诊断报告、影像测量、
  标注、MPR、三视图联动、三维体绘制或其他诊断能力。
- **DICOM lifecycle**: 本功能只读取 `002-dicom-import` 已持久化的受管 DICOM 文件和实例顺序，
  不改变导入五类报告、数据库记录或文件内容。缺失、不可查看或无法解码的文件必须明确报告，不得
  静默跳过、删除或修复既有数据。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 打开并连续浏览轴位 CT 序列 (Priority: P1)

本地用户从当前病人的影像检查列表选择一个可查看 CT Series，打开独立轴位查看页。系统显示该
Series 的中间切片，用户可以通过鼠标滚轮或上一张、下一张按钮按既定顺序浏览全部切片，并始终
看到当前切片和总切片数。

**Why this priority**: 能够可靠打开并按医学空间顺序浏览已导入的 CT 切片，是轴位查看器的核心价值。

**Independent Test**: 为一位病人导入至少三张可查看 CT 切片，从 Series 入口打开查看页，核对初始
切片、前后切换、首尾边界和切片计数，无需使用其他工具即可完整验证。

**Acceptance Scenarios**:

1. **Given** 当前病人拥有一个至少三张影像的可查看 CT Series，**When** 用户点击“打开轴位查看器”，
   **Then** 系统在独立查看页显示该 Series 的中间切片、病人/检查/序列摘要以及正确的当前/总切片数。
2. **Given** 查看器已显示一个多切片 Series，**When** 用户向前或向后滚动，**Then** 图像严格按
   既有实例顺序切换，切片计数同步更新且不会越过首张或末张。
3. **Given** 用户位于任意切片，**When** 用户点击上一张或下一张，**Then** 结果与同方向滚轮操作一致。
4. **Given** 用户退出查看器，**When** 返回病人管理页，**Then** 原病人详情和影像检查仍可继续使用。

---

### User Story 2 - 调整影像显示并恢复默认视图 (Priority: P2)

本地用户可以在轴位查看页选择窗宽窗位、平移或缩放工具，用主鼠标操作当前影像，并随时通过重置
恢复初始切片和默认显示状态。任一时刻只有一个主工具处于激活状态，当前工具在工具栏中清晰可见。

**Why this priority**: 基础显示调整能够帮助教学演示理解 CT 灰度和局部结构，同时保持范围小于测量、
标注或多平面重建。

**Independent Test**: 打开任意可查看 Series，依次选择三种工具并产生可见变化，再执行重置，核对
当前工具、图像位置、比例、灰度显示和初始切片均恢复预期。

**Acceptance Scenarios**:

1. **Given** 查看器已加载影像，**When** 用户选择窗宽窗位并拖动，**Then** 当前影像的灰度显示发生
   可见变化，切片顺序和病人数据不变。
2. **Given** 查看器已加载影像，**When** 用户选择平移或缩放并操作，**Then** 图像位置或比例发生
   可见变化，工具栏明确标识当前激活工具。
3. **Given** 用户已切换切片并调整显示，**When** 用户点击重置，**Then** 系统恢复初始中间切片、
   默认灰度显示、居中位置和适合视口的比例。
4. **Given** 用户退出后再次打开同一 Series，**When** 查看器完成加载，**Then** 上次切片、工具和
   显示调整不会被恢复。

---

### User Story 3 - 获得安全、可理解的不可查看与失败反馈 (Priority: P3)

本地用户在 Series 不可查看、DICOM 文件缺失、影像无法解码、序列为空或本机服务失败时，可以看到
稳定、可理解且不泄露内部信息的反馈，并能够重试或返回病人管理页。不可查看 Series 在进入查看器
之前即被阻止。

**Why this priority**: 本地影像文件可能被移动、损坏或使用当前不支持的编码；明确失败边界可以避免
用户误以为影像已成功显示或数据已被修改。

**Independent Test**: 分别使用不可查看 Series、移除一个受管文件并模拟服务失败，核对入口状态、
错误提示、重试/返回动作以及页面中不存在绝对路径、内部资源 ID和技术异常。

**Acceptance Scenarios**:

1. **Given** Series 标记为不可查看，**When** 用户查看检查列表，**Then** 打开动作不可用，并显示
   导入阶段保存的稳定原因。
2. **Given** 实例索引存在但受管 DICOM 文件缺失，**When** 查看器请求该影像，**Then** 系统明确
   提示本机文件缺失，保留重试和返回能力，且不显示文件路径。
3. **Given** DICOM 文件存在但无法由当前查看器解码，**When** 加载失败，**Then** 系统提示无法解码
   该影像，不显示 codec 堆栈或内部异常，也不改变既有文件和索引。
4. **Given** 本机服务不可连接或 Series 请求失败，**When** 查看页加载，**Then** 用户看到可理解的
   本机服务错误并可以重试或返回。

### End-to-End Acceptance Path *(mandatory)*

1. 启动只绑定本机地址并使用独立临时数据目录的应用。
2. 创建或选择一位虚构病人，导入一套至少三张、已脱敏且可查看的真实 CT DICOM Series。
3. 在病人详情的 Study/Series 列表确认可查看状态并打开轴位查看器。
4. 核对完整非临床提示、Patient/Study/Series 摘要、中间切片和当前/总切片数。
5. 使用滚轮和上一张/下一张浏览首张、中间和末张，核对顺序、计数和边界。
6. 依次验证窗宽窗位、平移、缩放和重置均产生预期可见行为。
7. 退出并再次打开同一 Series，确认未恢复上次浏览和工具状态。
8. 使用一个不可查看 Series，确认入口被阻止并显示原因。
9. 模拟一个受管文件缺失，确认错误可理解、可重试、不泄露路径且不改变其他数据。
10. 核对浏览器网络请求只访问本机服务，查看页、加载态和错误态均持续显示完整非临床提示。

### Edge Cases

- 只有一张切片时，初始显示第 1 张；上一张和下一张均不可用，计数为 `1 / 1`。
- 偶数张切片时，初始切片使用从 0 开始索引的 `floor(total / 2)`，例如 4 张时显示第 3 张。
- 快速连续滚动或点击时，最终切片不得越界，较早的异步加载结果不得覆盖较新的用户选择。
- Series 详情在入口显示 eligible、打开时已被删除或改为 unsupported 时，查看页必须重新校验并失败。
- 当前切片加载失败时，不得自动删除或跳过该实例；用户可以返回、重试或切换到已可用切片。
- 浏览器视口尺寸变化时，图像应继续适合可用画布，不遮挡安全提示或主要控制按钮。
- 用户在加载完成前退出时，未完成请求和查看器资源应被取消或释放，不产生后续页面错误。
- 用户仅使用键盘时，必须能够到达并操作返回、重试、切片导航、工具选择和重置控制，焦点状态清晰可见。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 只为标记为可查看且至少包含一个实例的 CT Series 提供可用的轴位查看入口。
- **FR-002**: 系统 MUST 为不可查看 Series 显示稳定原因，并 MUST NOT 允许其进入像素查看流程。
- **FR-003**: 系统 MUST 从当前 Patient 的 Study/Series 列表进入独立轴位查看页，并允许返回原病人上下文。
- **FR-004**: 轴位查看页 MUST 显示病人姓名和病历号、检查描述和日期、序列描述和实例数量；MUST NOT
  向用户显示内部资源 ID 或本机路径。
- **FR-005**: 系统 MUST 使用既有 Series 详情给出的 Instance 顺序作为切片浏览的唯一顺序。
- **FR-006**: 系统 MUST 在打开 Series 后默认显示 `floor(total / 2)` 对应的切片。
- **FR-007**: 系统 MUST 显示从 1 开始的当前切片编号和总切片数，并在每次切片变化后同步更新。
- **FR-008**: 用户 MUST 能够通过鼠标滚轮、上一张和下一张操作浏览切片。
- **FR-009**: 系统 MUST 阻止所有切片导航越过首张或末张，并在边界禁用相应按钮。
- **FR-010**: 用户 MUST 能够选择窗宽窗位、平移或缩放作为当前主鼠标工具。
- **FR-011**: 系统 MUST 保证任一时刻只有一个主鼠标工具处于激活状态，并清晰标识当前工具。
- **FR-012**: 用户 MUST 能够重置查看器；重置 MUST 恢复初始中间切片、默认灰度显示、居中位置和
  适合视口的比例。
- **FR-013**: 系统 MUST NOT 持久化当前切片、工具、平移、缩放或灰度显示状态；重新打开时必须使用默认状态。
- **FR-014**: 系统 MUST 通过 Instance 资源标识读取对应的受管 DICOM 文件，且 MUST NOT 接受客户端提供的文件路径。
- **FR-015**: 系统 MUST 校验被读取文件仍位于本机受管 DICOM 目录内，并拒绝绝对路径、目录逃逸和目录外目标。
- **FR-016**: 系统 MUST 以适合 DICOM 文件的响应类型返回影像资源，并 MUST NOT 在响应头、错误体
  或用户界面中暴露服务器绝对路径。
- **FR-017**: 当 Instance 不存在、Series 不可查看、文件缺失、Series 为空、解码失败或本机服务失败时，
  系统 MUST 显示彼此可区分的稳定、可理解反馈。
- **FR-018**: 查看失败 MUST NOT 自动跳过、删除、覆盖或修改既有 Instance 索引和受管 DICOM 文件。
- **FR-019**: 加载和失败状态 MUST 提供返回病人管理页的操作；可恢复的请求失败还 MUST 提供重试操作。
- **FR-020**: 查看页卸载、Series 切换或加载取消时，系统 MUST 释放该页面创建的影像查看资源并停止
  对已离开页面的状态更新。
- **FR-021**: 病人管理页、Series 入口、轴位查看页、加载状态和失败状态 MUST 持续、清晰地显示完整
  “教学演示软件，不用于临床诊断”提示。
- **FR-022**: 所有病人、影像元数据、DICOM 文件和解码像素 MUST 保留在本机；本功能发出的网络请求
  MUST 仅访问本机服务。
- **FR-023**: 系统 MUST 保持一个单轴位 Series 视口，不得在本功能中加入多视口或跨平面联动。
- **FR-024**: 返回、重试、切片导航、工具选择和重置等控制 MUST 具有可理解的文字名称并可通过
  键盘操作；当前工具、切片计数和错误信息不得只通过颜色或画布像素表达。

### Non-Goals *(mandatory)*

- 不实现 MPR、冠状位/矢状位视图、三视图联动或三维体绘制。
- 不实现测量、标注、分割、截图报告、诊断报告或临床决策支持。
- 不实现 PACS、DICOMweb、远程 URL 加载、云存储、遥测、账户、登录或权限。
- 不实现浏览状态持久化、书签、最近查看列表或深链接。
- 不修改 DICOM 导入分类、实例排序规则、受管文件内容或病人删除生命周期。

### Key Entities *(include if feature involves data)*

- **Viewer Context**: 当前一次查看所需的 Patient、Study 和 Series 用户可见摘要；仅在当前页面会话中存在。
- **Viewable Series**: 已导入、标记为可查看且含有一个或多个有序 Instance 的 CT Series。
- **Instance Resource**: 通过内部资源标识定位的单个受管 DICOM 文件；用户界面不显示标识和路径。
- **Viewer Session**: 从打开 Series 到退出或页面卸载期间的临时切片、工具和显示状态；不持久化。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在已有病人详情和 eligible Series 的前提下，用户可在不超过 3 次可见操作内打开轴位图像。
- **SC-002**: 对包含至少 3 张切片的验收 Series，首张到末张的 100% 切片均可按既定顺序访问，
  当前/总切片数在所有导航操作后保持正确。
- **SC-003**: 窗宽窗位、平移、缩放和重置四项操作在真实浏览器验收中均产生可观察且符合说明的结果。
- **SC-004**: 单张、奇数张和偶数张 Series 的初始切片及首尾边界在全部自动化场景中 100% 符合规则。
- **SC-005**: unsupported、文件缺失、解码失败和服务失败四类验收场景均提供可理解反馈、返回能力，
  且用户可见内容中不存在绝对路径、内部资源 ID 或技术堆栈。
- **SC-006**: 退出并重新打开同一 Series 的全部验收中，切片、工具、平移、缩放和灰度调整均恢复默认状态。
- **SC-007**: 真实浏览器验收期间 100% 影像和元数据网络请求仅访问本机地址，所有相关页面和状态均显示完整非临床提示。
- **SC-008**: 适用的后端、前端自动化测试、生产构建和完整真实浏览器验收路径全部通过后，本功能才视为完成。
- **SC-009**: 在验收环境中，从 eligible Series 点击打开到首张轴位影像可见的时间不超过 5 秒。

## Assumptions

- 一名本地用户在桌面浏览器中操作，输入数据为已脱敏的教学 CT DICOM。
- `002-dicom-import` 已提供 Patient → Study → Series 列表、eligible/unsupported 状态及确定性 Instance 顺序。
- 初始切片采用 `floor(total / 2)`；这是用户未指定时的推荐默认。
- 本功能优先保证未压缩和当前查看器可解码的已导入 CT；unsupported Series 在入口被阻止。
- 页面刷新可回到病人管理页，查看器状态不需要跨刷新恢复。
- 本功能不依赖任何外部服务，也不要求修改既有持久化数据模型。
