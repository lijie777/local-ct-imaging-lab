# Feature Specification: DICOM 导入与持久化

**Feature Branch**: `002-dicom-import`

**Created**: 2026-07-20

**Status**: Complete

**Input**: User description: "继续完成 DICOM 导入与持久化；采用推荐默认，删除病人时同步删除其检查、序列、实例索引和受管 DICOM 文件。"

## Constitutional Constraints *(mandatory)*

- **Safety notice**: 病人管理页、检查和序列列表、导入进度、导入报告、加载状态、空状态及失败状态
  顶部必须持续、清晰地显示“教学演示软件，不用于临床诊断”。DICOM 导入覆盖式界面不得遮挡该
  提示；无法保持底层提示清晰可见时，覆盖式界面内必须重复显示完整提示。
- **Data boundary**: 本功能仅供一名本地用户离线使用。病人信息、DICOM 元数据、原始像素文件、
  导入报告和日志必须保留在本机，不得上传、同步、遥测或发送到任何外部服务。服务重启后已成功
  导入的数据仍可访问。
- **Scope boundary**: 本功能不得加入云服务、登录认证、PACS、DICOMweb、诊断报告、影像测量、
  三维体绘制、轴位查看器、MPR 或其他像素显示能力。
- **DICOM lifecycle**: 每个输入文件必须明确归入成功、重复、跳过、不支持或失败五类之一；五类
  分别计数，所有非成功项保留文件标识和原因。部分失败不得破坏无关成功数据；数据库失败必须
  回滚对应记录并清理本次新增受管文件；删除病人时必须同步删除其检查、序列、实例索引和受管
  DICOM 文件，任何失败不得被报告为完全成功。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 导入并持久保存真实 CT 数据 (Priority: P1)

本地用户选择一位已有病人，从本机选择一组已脱敏的 CT DICOM 文件或文件夹。系统读取文件，
确认数据属于当前病人，按检查、序列和实例组织，并在病人详情下显示检查和序列摘要。关闭并重新
启动本地服务后，已导入的数据仍然存在。

**Why this priority**: 没有真实 DICOM 数据的可靠导入和持久化，后续轴位查看器与三视图功能没有
可用的数据基础。

**Independent Test**: 预置一位病人，导入一套已脱敏 CT 序列，核对检查、序列、实例数量和病人
检查摘要；重启本地服务后再次打开同一病人，所有已成功导入的记录仍可见。

**Acceptance Scenarios**:

1. **Given** 已存在与 DICOM PatientID 匹配的病人，**When** 用户导入一组有效 CT 文件，
   **Then** 每个新实例报告为成功或不支持，检查和序列出现在该病人下，输入文件不会离开本机。
2. **Given** 一套 CT 数据包含多个序列，**When** 导入完成，**Then** 系统按检查和序列标识正确
   分组，并显示每个序列的实例数量和是否具备后续查看条件。
3. **Given** 已成功导入数据，**When** 本地服务重启并重新打开病人，**Then** 病人检查数量、最近
   检查日期、检查列表和序列摘要与重启前一致。
4. **Given** 用户打开 DICOM 导入覆盖式界面，**When** 该界面显示或正在导入，**Then** 完整非临床
   提示持续清晰可见，且界面明确显示当前选择的病人。

---

### User Story 2 - 获得可追踪的部分失败与重复报告 (Priority: P2)

本地用户可以混合选择有效 CT、重复文件、非 DICOM、损坏 DICOM、非 CT、病人不匹配和后续
查看器暂不支持的 CT 文件。系统完成可以安全完成的部分，并逐文件说明其余文件的类别和原因，
不得静默忽略问题。

**Why this priority**: 真实目录经常混有重复或异常文件。只有明确、可核对的部分成功报告，用户
才能判断哪些数据已保存并安全重试。

**Independent Test**: 在一次导入中混合有效、重复、损坏、非 CT 和病人不匹配文件，核对五类
计数总和等于输入文件总数；确认有效数据保留、异常数据有明确原因，并且重新导入不会产生重复记录。

**Acceptance Scenarios**:

1. **Given** 某实例标识已存在，**When** 用户再次导入相同文件，**Then** 文件报告为重复，不新增
   实例记录，也不新增受管副本。
2. **Given** 同一次导入同时包含有效文件和损坏文件，**When** 导入结束，**Then** 无关有效数据成功
   保存，损坏文件报告为失败并说明无法读取。
3. **Given** 文件可识别但不是 CT，**When** 导入结束，**Then** 文件报告为跳过并说明当前功能只
   接受 CT。
4. **Given** 某检查中的 PatientID 与当前病人不匹配或组内 PatientID 不一致，**When** 导入结束，
   **Then** 该检查组全部被阻止并逐项报告，其他匹配检查不受影响。
5. **Given** CT 元数据可读取但缺少后续查看所需条件，**When** 导入结束，**Then** 文件报告为
   不支持，元数据和本地文件仍可保留，所属序列明确显示不可查看原因。
6. **Given** 某检查组保存失败，**When** 系统返回报告，**Then** 该组本次新增记录和受管文件全部
   清理，之前已成功的数据和其他成功检查保持不变。

---

### User Story 3 - 浏览检查并安全删除全部本地数据 (Priority: P3)

本地用户可以在病人详情下查看已导入检查和序列摘要。当用户明确确认删除病人时，系统同时删除
病人、检查、序列、实例索引及其受管 DICOM 文件；删除失败时不得报告成功或留下数据库指向缺失
文件的状态。

**Why this priority**: 用户需要确认导入结果，也必须能够可靠清理包含本地医疗数据的完整病人目录。

**Independent Test**: 为一位病人导入 CT 数据，核对检查和序列列表；先取消删除确认数据不变，
再确认删除并核对数据库索引和受管目录同时消失；重启服务后病人和影像数据均不恢复。

**Acceptance Scenarios**:

1. **Given** 病人已有检查和序列，**When** 用户打开病人详情，**Then** 系统显示确定排序的检查列表、
   序列数量、实例数量、检查日期和查看条件，不显示受管文件绝对路径。
2. **Given** 用户取消删除病人，**When** 删除确认关闭，**Then** 病人、检查、序列、实例和受管文件
   全部保持不变。
3. **Given** 用户明确确认删除，**When** 删除成功，**Then** 病人及其全部影像索引和受管文件同时
   删除，病人从列表中消失。
4. **Given** 删除过程中的数据库或文件操作失败，**When** 操作结束，**Then** 系统显示失败，不得
   报告完全成功，并恢复到可重试且数据库与受管文件一致的状态。
5. **Given** 病人及影像数据已成功删除，**When** 本地服务重启，**Then** 病人、检查和受管文件均
   不恢复。

### End-to-End Acceptance Path *(mandatory)*

1. 用户创建或选择病历号与已脱敏 CT PatientID 匹配的病人，页面显示完整非临床提示。
2. 用户打开 DICOM 导入界面，选择一套真实已脱敏 CT 文件夹并开始导入。
3. 导入结束后，用户核对五类计数、逐文件结果、检查数量、最近检查日期、检查和序列摘要。
4. 用户再次导入同一文件夹，核对既有实例全部报告为重复，数据库记录和受管文件数量不增加。
5. 用户混合导入有效 CT、损坏文件和非 CT 文件，核对有效数据保留且每个异常文件有明确类别和原因。
6. 用户重启前后端并刷新浏览器，核对病人检查摘要、检查、序列和实例数量保持不变。
7. 用户发起删除后先取消，确认全部数据仍存在；再次发起并确认删除，核对病人、影像索引和受管
   文件同时消失。
8. 用户再次重启服务，确认已删除病人及其影像数据没有恢复，浏览器请求始终限于本机。

### Edge Cases

- 未选择任何文件、选择空文件或上传过程中本机磁盘写入失败时，系统拒绝或终止对应文件并明确说明。
- 非 DICOM 文件被跳过；可识别但损坏或缺失检查、序列、实例必需标识的文件报告为失败。
- 非 CT 文件被跳过并说明当前功能只接受 CT。
- 缺失 PatientID 的文件被跳过；PatientID 比较忽略首尾空白和英文字母大小写，但不做模糊匹配。
- 同一检查组出现不同 PatientID，或检查标识已归属于另一位病人时，整个检查组被阻止。
- 同一输入批次内重复实例和数据库中已存在的实例都只计入重复，不覆盖已有受管文件。
- CT 元数据可读取但传输语法、像素信息、尺寸或空间信息不足时，数据可以保留但必须标记不支持，
  并显示稳定原因。
- 同一检查包含多个序列时，各序列分别汇总；序列内尺寸或方向不一致时不得误标记为可查看。
- 单个文件或单个检查组失败不得回滚无关检查组；检查组事务失败不得留下本次新增记录或文件。
- 目标路径已有未知文件但数据库没有对应实例时，不得静默覆盖或当作重复，必须报告存储冲突。
- 导入界面在网络、文件或持久化失败后保持打开并保留当前报告，只有用户明确关闭或新建导入时清理。
- 服务重启后无需恢复尚未提交的浏览器文件选择，但必须恢复已成功导入的数据。
- 删除没有影像数据的病人仍按原有行为成功；删除有影像数据的病人必须处理全部索引和受管文件。
- 删除失败时不得出现数据库仍引用已不存在文件的状态，也不得删除其他病人的目录。
- 用户可见响应不得泄露本机绝对路径、数据库细节、堆栈或原始技术异常。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 允许本地用户在选中的已有病人下选择一个或多个本机文件或文件夹进行
  DICOM 导入，且无需登录或外网连接。
- **FR-002**: 导入界面 MUST 显示当前病人身份、文件选择、导入状态、完整非临床提示和取消/关闭
  行为；进行中的导入不得被重复提交。
- **FR-003**: 系统 MUST 逐文件读取 DICOM 元数据，并且不得为分类或索引而解码或向外发送像素数据。
- **FR-004**: 系统 MUST 仅接受 CT 数据进入检查索引；非 DICOM 和非 CT 文件 MUST 明确跳过，损坏
  或缺失必需标识的文件 MUST 明确失败。
- **FR-005**: 系统 MUST 使用检查、序列和实例的标准唯一标识组织数据；每个实例标识在全部本地
  数据中 MUST 唯一。
- **FR-006**: 系统 MUST 使用去除首尾空白且忽略英文字母大小写的精确规则比较 DICOM PatientID
  与当前病历号；缺失、不匹配或组内不一致 MUST 阻止对应检查组导入。
- **FR-007**: 系统 MUST 将每个输入文件归入成功、重复、跳过、不支持或失败五类之一，分别计数，
  且五类计数之和 MUST 等于输入文件总数。
- **FR-008**: 所有非成功项 MUST 显示原始文件标识、稳定原因代码和用户可理解的原因；不得静默
  忽略解析、校验、复制或持久化错误。
- **FR-009**: 已存在的实例 MUST 报告为重复，且 MUST NOT 新增实例记录、覆盖受管文件或改变
  先前成功数据。
- **FR-010**: 不支持后续查看条件但元数据可读取的 CT 文件 MUST 报告为不支持；系统 MAY 保留其
  元数据和受管文件，但所属序列 MUST 显示不可查看原因。
- **FR-011**: 系统 MUST 允许一次导入部分成功；单个文件或检查组失败 MUST NOT 删除或回滚其他
  已成功检查组和之前导入的数据。
- **FR-012**: 检查组持久化失败时，系统 MUST 回滚该组本次新增索引并清理该组本次新增受管文件；
  先前已存在文件 MUST NOT 被删除。
- **FR-013**: 系统 MUST 将已成功或不支持的原始 DICOM 文件保存在本机受管目录，将结构化元数据
  和相对受管路径保存在本机索引中；客户端文件名 MUST NOT 决定最终存储路径。
- **FR-014**: 系统 MUST 防止最终受管路径逃逸数据目录、覆盖未知文件或访问其他病人的受管目录。
- **FR-015**: 本地服务重启后，所有已成功提交的检查、序列、实例、查看条件和受管文件 MUST 保持
  可访问，未提交的浏览器文件选择无需恢复。
- **FR-016**: 病人列表和详情中的检查数量与最近检查日期 MUST 根据已保存检查派生；没有检查时
  继续显示数量 0 和空日期。
- **FR-017**: 系统 MUST 在病人详情下显示检查列表，并允许查看每个检查的序列摘要、实例数量、
  检查日期和查看条件；列表 MUST 使用确定排序且不得显示受管文件绝对路径。
- **FR-018**: 检查、序列和导入报告的加载、空、成功和失败状态 MUST 持续显示完整非临床提示。
- **FR-019**: 用户取消删除病人 MUST 保持病人、全部影像索引和受管文件不变。
- **FR-020**: 用户确认删除病人后，系统 MUST 同步删除病人、检查、序列、实例索引和该病人的受管
  DICOM 文件，并在重启后保持删除结果。
- **FR-021**: 删除过程发生数据库或文件错误时，系统 MUST 显示失败，不得报告完全成功，并 MUST
  恢复为可重试且数据库与受管文件一致的状态。
- **FR-022**: 病人和 DICOM 数据、导入报告及日志 MUST 只保留在本机，不得上传、同步、遥测或
  发送到任何外部服务。
- **FR-023**: 用户可见错误和报告 MUST NOT 包含本机绝对路径、数据库语句、堆栈或内部异常详情。
- **FR-024**: 本功能 MUST NOT 提供像素显示、轴位查看器、MPR、测量、报告、PACS、DICOMweb、
  登录认证、云服务或三维体绘制。

### Non-Goals *(mandatory)*

- 不显示、渲染或处理 CT 像素，不实现轴位、冠状位、矢状位或三视图联动。
- 不实现窗宽窗位、滚动切片、平移、缩放、测量、标注或三维体绘制。
- 不连接 PACS、Orthanc、DICOMweb、HIS、RIS 或任何外部医疗系统。
- 不实现账户、登录、权限、多用户并发、远程访问、云存储、同步、遥测或外部备份。
- 不生成诊断报告，不支持临床诊断、治疗决策或医疗设备工作流。
- 不提供后台任务队列、断点续传、跨设备导入或远程目录扫描。

### Key Entities *(include if feature involves data)*

- **Import Session（导入会话）**: 代表用户一次文件或文件夹选择，包含输入文件总数、五类结果和
  每个非成功文件的原因；会话本身不要求跨重启恢复。
- **Study（检查）**: 属于一位病人的 DICOM 检查，由全局唯一检查标识区分，包含 PatientID、检查
  日期、描述和若干序列。
- **Series（序列）**: 属于一个检查，由全局唯一序列标识区分，包含模态、序列号、尺寸摘要、实例
  数量、查看条件和不可查看原因。
- **Instance（实例）**: 属于一个序列，由全局唯一实例标识区分，包含排序和空间元数据以及一个本机
  受管 DICOM 文件引用。
- **Managed DICOM File（受管文件）**: 成功保存到本机数据目录的原始 DICOM 文件；其生命周期必须
  与对应实例索引及病人删除保持一致。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 验收人员能够在一次连续浏览器流程中为选定病人导入一套至少包含 50 个实例的已脱敏
  CT 数据，并在导入完成后看到正确的检查、序列和实例数量。
- **SC-002**: 对每次导入，100% 输入文件被归入成功、重复、跳过、不支持或失败之一，五类计数之和
  等于输入文件总数，100% 非成功项显示文件标识和原因。
- **SC-003**: 重新导入相同数据时，100% 已存在实例报告为重复，数据库实例数量和受管文件数量均
  不增加。
- **SC-004**: 混合有效、损坏、非 CT 和病人不匹配文件时，100% 无关有效检查组保持成功，100%
  异常文件或受阻检查组得到明确结果，既有成功数据不丢失。
- **SC-005**: 对所有模拟持久化失败，失败检查组本次新增索引和受管文件残留均为 0，其他成功组和
  之前成功数据保持不变。
- **SC-006**: 本地服务重启后，100% 已成功提交的检查、序列、实例数量、查看条件和病人检查摘要与
  重启前一致。
- **SC-007**: 100% 的导入界面、导入进度、导入报告、检查/序列列表及其加载、空和失败状态保持完整
  非临床提示可见，且用户界面不显示本机绝对路径。
- **SC-008**: 用户取消删除后，100% 病人索引和受管文件保持不变；确认删除成功后，病人、全部影像
  索引及该病人受管目录残留均为 0，并在重启后保持删除状态。
- **SC-009**: 在导入、浏览、重启和删除的完整验收过程中，100% 网络请求仅访问本机地址，病人和
  DICOM 数据不发送到外部服务。
- **SC-010**: 验收人员可以仅依据导入报告和检查/序列状态判断每个输入文件是否已保存、重复、跳过、
  不支持或失败，无需查看服务器日志或数据库。

## Assumptions

- 一名本地用户操作应用，通常不会对同一病人同时发起多个导入；并发请求仍不得绕过唯一性和
  一致性约束。
- 导入数据为教学用途的已脱敏 CT；用户负责在导入前获得合法使用权限。
- 浏览器文件夹选择会把目录中的文件作为一次导入提交；服务不扫描用户任意本机路径。
- PatientID 只与病历号按去除首尾空白且忽略英文字母大小写的精确规则比较，不使用姓名、模糊匹配
  或自动改写病人资料。
- 检查标识、序列标识和实例标识按 DICOM 全局唯一标识处理；已归属于其他病人的检查不得迁移。
- 元数据可读但后续查看条件不足的数据允许本地保留并标记不支持，是否可查看由后续独立 Feature
  最终确认。
- 本功能按检查组提供部分成功；导入会话和未提交的文件选择无需跨页面刷新或服务重启恢复。
- 本机剩余磁盘空间不足属于可报告失败，不要求本功能自动释放空间或管理外部存储。
- 依赖已完成的 `001-patient-management`，不依赖尚未实现的查看器或 MPR。
