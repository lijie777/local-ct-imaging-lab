# Feature Specification: 后台导入与断点续传

**Feature Branch**: `007-background-import-resume`

**Created**: 2026-07-23

**Status**: Complete

**Input**: 用户要求在查看器状态持久化之后实现后台导入与断点续传，并按推荐方案持续执行。

## Constitutional Constraints

- **Safety notice**: 病人管理和 DICOM 导入页面持续显示“教学演示软件，不用于临床诊断”或
  语义等价提示，导入进度或错误状态不得遮挡或弱化该提示。
- **Data boundary**: 文件清单、续传进度、暂存内容、DICOM 数据和报告全部保留在本机单用户
  服务，不访问外网，不把文件内容或元数据发送给第三方。
- **Scope boundary**: 本功能不加入认证、云服务、PACS、DICOMweb、诊断报告或高级 3D；
  体绘制、表面重建和 MIP 由 Feature 008 独立规格化和验收。
- **DICOM lifecycle**: 后台导入继续逐文件报告成功、重复、跳过、不支持和失败；中断、重启、
  部分失败和病人删除后，数据库、受管 DICOM 文件、任务记录和暂存文件必须保持一致。

## User Scenarios & Testing

### User Story 1 - 中断后继续上传 (Priority: P1)

用户选择一批本机 DICOM 文件或文件夹开始导入后，即使刷新页面、关闭导入对话框或本机连接
短暂失败，也能重新选择同一批文件并从服务端最后确认的位置继续，不必从头上传已确认内容。

**Why this priority**: 大批 CT 文件上传时间长；没有可靠续传，任何页面或连接中断都会浪费时间，
也无法形成可用的后台导入基础。

**Independent Test**: 选择一批脱敏文件，上传到 30%–70% 时刷新页面，重新选择同一文件夹；
系统识别已有任务，只上传剩余字节，最终所有文件完整进入待处理状态。

**Acceptance Scenarios**:

1. **Given** 一项上传任务已确认部分字节，**When** 用户刷新并重新选择同一批文件，**Then**
   每个文件从自己的确认位置继续，总进度不回退到零。
2. **Given** 用户重新选择的文件与原清单路径、大小或内容身份不匹配，**When** 尝试续传，
   **Then** 系统拒绝混合内容、保留原任务并明确指出需要选择原文件或放弃任务。
3. **Given** 上传请求在一个数据块中途失败，**When** 用户重试，**Then** 只从服务端已确认
   offset 继续，磁盘和任务记录不包含重复或跳跃字节。

---

### User Story 2 - 上传完成后后台处理 (Priority: P2)

用户完成文件上传后可以关闭导入对话框，导入仍在本机后台继续；重新打开对话框可看到排队、
处理中或完成状态，完成后继续得到五类逐文件报告和最新 Study/Series。

**Why this priority**: DICOM 解析、校验、复制和数据库更新不应锁住对话框或要求用户一直等待，
但必须复用现有可追踪报告和一致性规则。

**Independent Test**: 上传完成后立即关闭对话框，继续使用病人页面；后台完成后重新打开对话框，
看到完整报告，并在同一病人下看到成功导入的 Study/Series。

**Acceptance Scenarios**:

1. **Given** 所有文件均已完整上传，**When** 用户启动后台处理并关闭对话框，**Then** 任务继续，
   同一时间只处理一个本机导入任务。
2. **Given** 后台处理结束，**When** 用户重新打开导入对话框，**Then** 显示成功、重复、跳过、
   不支持和失败的独立计数与逐文件原因，并刷新 Study/Series。
3. **Given** 某些文件解析或保存失败，**When** 任务完成，**Then** 这些文件进入对应非成功分类，
   其他成功文件不被误删，任务仍以一份完整报告结束。

---

### User Story 3 - 服务重启与安全清理 (Priority: P3)

用户或系统重启本机 FastAPI 进程后，未完成上传仍可续传，已排队或正在处理的任务可恢复执行；
用户也可以放弃未处理任务，且病人删除不会与活动导入竞态。

**Why this priority**: 任务必须跨进程生命周期保持可信，避免孤立暂存文件、重复后台处理或病人
已删除后仍写入影像。

**Independent Test**: 分别在部分上传和后台处理中重启服务；前者保留 offset，后者恢复为可执行
任务并最终结束。活动任务期间删除病人被安全阻止，任务终态后删除可完成且无残留。

**Acceptance Scenarios**:

1. **Given** 任务处于部分上传，**When** 服务重启，**Then** 清单、确认 offset 和暂存内容保留，
   用户可重新选择原文件继续。
2. **Given** 任务处于后台处理中，**When** 服务异常退出并重启，**Then** 任务重新进入待处理状态，
   已由现有导入规则提交的数据安全识别为重复，未提交数据继续处理。
3. **Given** 病人存在上传中、排队或处理中的任务，**When** 用户删除病人，**Then** 删除被明确
   阻止；任务完成或被放弃后可正常删除，任务记录与暂存文件不残留。

### End-to-End Acceptance Path

1. 创建虚构病人，选择包含可成功、重复、跳过、不支持和失败样本的脱敏 CT 文件夹。
2. 开始上传，在 30%–70% 时刷新页面；重新打开导入对话框并选择同一文件夹，核对只发送各文件
   未确认部分且总进度继续增长。
3. 再次暂停，重启同一 FastAPI 服务和同一数据目录，重新选择文件并完成上传。
4. 启动后台处理后关闭对话框；重新打开，核对 queued/running 状态。处理中再次重启服务，确认
   任务恢复并最终完成，没有并行执行第二个任务。
5. 核对五类计数总和等于文件总数、每项有文件标识和原因，成功 Study/Series 可查看，数据库和
   受管文件一致。
6. 创建另一项部分上传任务，选择一项同名同大小但内容身份不同的文件，确认续传被拒绝；放弃
   任务后暂存内容被清理。
7. 活动任务期间尝试删除病人，确认安全阻止；任务终态后删除，确认任务、暂存和受管文件无残留。
8. 在 1280×900 与 820×900 下核对进度、错误、按钮和非临床提示可见；console/network 无外部
   请求、路径泄漏或未处理错误。

### Edge Cases

- 空清单、超过 2,000 个文件、单文件超过 512 MiB 或总量超过 8 GiB 时，创建任务整体拒绝。
- 相对路径为空、绝对、含 `.`/`..`、控制字符、重复路径或无法稳定识别时，整体拒绝且不创建暂存。
- 同一病人已有上传中、排队或处理任务时，不允许创建第二个活动任务。
- 服务端实际暂存长度大于数据库确认 offset 时丢弃未确认尾部；短于确认 offset 时回退到实际长度，
  不跳过丢失字节。
- 最后一块上传完成但文件内容身份不匹配时不得入队，既有数据库与受管 DICOM 不受影响。
- 正常的 DICOM 单文件失败属于完成报告；本机数据库、暂存或 worker 基础设施失败进入安全失败状态。
- 后台重启后已提交 Study/Instance 可报告为重复，但不得复制第二份受管文件或产生重复数据库记录。
- 用户关闭对话框时，浏览器上传可暂停；已排队或处理的服务端任务不得被关闭动作取消。

## Requirements

### Functional Requirements

- **FR-001**: 系统 MUST 为一次文件或文件夹选择创建持久化导入任务和有序文件清单。
- **FR-002**: 每个病人同一时间 MUST 最多有一个上传中、排队或处理中的活动任务。
- **FR-003**: 清单 MUST 保存足以重新匹配同一本机文件的相对路径、大小、修改时间和内容身份。
- **FR-004**: 系统 MUST 维持现有 1–2,000 文件、单文件 512 MiB、批次 8 GiB 限制。
- **FR-005**: 上传 MUST 按文件顺序和服务端确认 offset 推进；客户端不得自行假设未确认字节成功。
- **FR-006**: 每次上传的数据块 MUST 不超过 4 MiB，offset 冲突或越界 MUST 安全拒绝并返回
  当前确认位置。
- **FR-007**: 页面刷新、对话框关闭、网络失败和本机服务重启后，已确认 offset MUST 保留。
- **FR-008**: 重新选择的文件与原清单不匹配时 MUST 拒绝续传，不得把两个文件内容拼接。
- **FR-009**: 只有全部文件完整且内容身份核对通过时，任务才可进入后台处理队列。
- **FR-010**: 本机服务 MUST 串行处理后台任务，同一时间最多执行一个导入任务。
- **FR-011**: 后台处理 MUST 复用现有 DICOM 解析、五类报告和数据库/受管文件一致性规则。
- **FR-012**: 上传完成后用户 MUST 可以关闭对话框，排队或处理中的任务继续执行。
- **FR-013**: 用户重新打开对话框时 MUST 看到最新任务、文件/字节进度、状态、错误或完成报告。
- **FR-014**: 服务启动时遗留的处理中任务 MUST 恢复为待处理并继续，部分上传任务保持可续传。
- **FR-015**: 用户 MUST 可以放弃上传中或终态任务并清理其暂存内容；排队或处理中的任务不得
  在无安全取消边界时被删除。
- **FR-016**: 活动导入任务存在时 Patient 删除 MUST 返回安全冲突，不得与上传或 worker 竞态。
- **FR-017**: 任务终态或 Patient 删除后，数据库任务/文件行和本机暂存目录 MUST 无孤立残留。
- **FR-018**: 错误 MUST 使用稳定安全代码和中文消息，不得泄露绝对路径、SQL、堆栈或 DICOM 内容。
- **FR-019**: 既有同步导入接口和既有成功数据 MUST 保持兼容，不因新任务功能被删除或迁移失败。
- **FR-020**: 所有任务、上传、轮询和数据流 MUST 只使用本机 loopback，不得访问外部服务。
- **FR-021**: 主要病人与导入界面 MUST 持续显示非临床教学提示并提供可访问的进度和错误状态。

### Non-Goals

- 跨设备、跨浏览器或无需重新选择本机文件的续传。
- 远程目录扫描、监控文件夹、网络共享自动导入、PACS 或 DICOMweb。
- 多用户队列、并行上传、并行 worker、优先级、暂停运行中的 pydicom 或任务历史中心。
- Redis、Celery、消息队列、独立 worker 服务、云存储或遥测。
- DICOM 修改、匿名化、诊断报告、分割、3D 体绘制、表面重建或 MIP。

### Key Entities

- **Import Job**: 某位病人的一次持久化导入，包含状态、总文件/字节、上传进度、最终报告和时间。
- **Import Job File**: 有序输入文件，包含安全相对路径、大小、内容身份和服务端确认 offset。
- **Import Report**: 现有五类计数与逐文件结果，正常处理结束后作为任务终态保存。
- **Resumable Staging Content**: 仅属于一个任务和文件、可跨刷新/重启保留、终态后清理的本机字节。

## Success Criteria

### Measurable Outcomes

- **SC-001**: 在上传进度 30%–70% 之间执行页面刷新或服务重启的全部验收中，续传成功率为 100%，
  已确认字节重复上传量为 0。
- **SC-002**: 同名同大小但内容身份不同的文件混合续传成功次数为 0。
- **SC-003**: 2,000 文件和 8 GiB 边界内，任务状态与聚合字节进度在用户操作后 1 秒内可见。
- **SC-004**: 上传完成后关闭对话框的全部验收中，后台任务完成率为 100%，同时运行任务数不超过 1。
- **SC-005**: 在 running 状态重启本机服务的全部验收中，任务恢复并到达 completed 或安全 failed
  终态，永久卡在 running 的任务数为 0。
- **SC-006**: 每份完成报告的五类计数总和与文件总数一致率为 100%，非成功项文件标识和原因完整率为 100%。
- **SC-007**: 中断、失败、放弃、重启和 Patient 删除验收后，孤立任务行、暂存目录、数据库记录
  指向缺失文件或未索引受管文件的数量均为 0。
- **SC-008**: 全量前后端测试、空库迁移、production build 和真实浏览器端到端路径全部通过。
- **SC-009**: 验收期间外部网络请求数为 0，非临床提示在主要页面持续可见。

## Assumptions

- 一名本机用户操作；同一病人无需同时进行多个导入任务。
- 用户愿意在刷新或重启后重新选择原文件/文件夹，浏览器不会在未授权时重新读取本机文件。
- 已确认 offset 是续传真值；进程异常退出时允许安全重传最后一个未确认数据块。
- 现有 `import_dicom_files` 的按 Study 事务、SOP Instance UID 去重和五类报告语义继续作为处理边界。
- 现有同步 multipart 导入暂时保留，新的对话框流程使用持久化任务接口。
